# 요구사항 변경 분석 리포트

## 요약

- 기획 변경 4건 → 요구사항 4건
- 정책 충돌 의심 1건, 기획 확인 질문 3건
- TC 생성 9건 → 채택 8건 (자동 6 / 수동 2), 반려 1건
- 커버리지 누락: 요구사항 1건, 정책 조항 1건
- 기존 스크립트 6개 중 4개 선정 실행
- 결함 의심 1건, 스크립트 갱신 필요 1건

## 1. 기획 변경점

| ID | 구분 | 영역 | 이전 | 변경 |
| --- | --- | --- | --- | --- |
| C1 | 변경 | 예상 도착 시간 | 가게가 접수하기 전에는 예상 도착 시간 대신 "가게 확인 중"을 표시한다. | 가게가 접수하기 전에는 예상 도착 시간 대신 "도착 시간 계산 중"을 표시한다. |

## 2. 정책 검토

**정책 충돌 의심 (기획 확인 전까지 해당 요구사항 TC 보류)**

- R4 ↔ [CPN-01] "쿠폰은 주문 1건당 1장만 사용할 수 있다"  
  정책상 주문당 쿠폰은 1장만 쓸 수 있어 '여러 장 적용' 상황이 생길 수 없음. 쿠폰 정책이 바뀌는 것인지, 쿠폰 + 다른 할인(멤버십 할인 등)을 함께 표시하라는 뜻인지 확인 필요

**정책에서 파생된 확인 조건 (기획서에는 없는 것)**

- R2 [ORD-CANCEL-02] 주문 후 5분이 지나면 접수 대기 상태여도 주문 취소 버튼이 보이지 않아야 한다 (4분 59초 / 5분 1초 경계)
- R2 [ORD-CANCEL-03] 쿠폰을 쓴 주문을 취소하면 결제 금액 전액 환불과 함께 쿠폰이 복원되어야 한다
- R3 [CPN-03] 할인 금액은 '-1,000원'처럼 음수 기호와 함께 표시되어야 한다
- R3 [CPN-02] 할인 금액이 주문 금액(배달팁 제외)보다 큰 쿠폰은 주문 금액까지만 할인되어야 한다
- R3 [PAY-02] 할인 후 결제 금액이 0원 미만으로 표시되면 안 된다

**기획 확인 질문**

- '주문 후 5분'의 기준 시각이 결제 완료 시각인지, 주문 요청 시각인지
- 5분이 지난 뒤에는 취소 버튼 대신 고객센터 연결 안내를 보여 주는지
- 쿠폰명이 길 때 줄바꿈과 말줄임 중 어떤 규칙을 따르는지
